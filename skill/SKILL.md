# 逐字稿提取 Skill

## 1. 这个 Skill 做什么

把「音视频内容」变成「可阅读、可下载的逐字稿」，并保证每一步的处理方式对用户可见、可解释。

它定义的是**工作流与判断规则**：

- 输入应该怎么判断；
- 什么情况下走字幕、什么情况下走语音识别；
- 失败了怎么降级、怎么给用户交代；
- 输出应该长什么样。

## 2. 这个 Skill 不负责什么

- 不提供下载能力，下载由后端 API 完成；
- 不替代后端代码：真正的执行者是 `backend/app/` 下的服务层；
- 不替代 `yt-dlp` / FFmpeg / faster-whisper；
- 不依赖 GPT、Claude、DeepSeek 等任何大模型。**产品在完全不加载 LLM 的情况下必须能跑通全部核心流程**；
- 不做动态规划：整体是一条带条件分支的确定性工作流，不是自主 Agent。

## 3. 输入判断

```text
输入
├─ 本地文件 → 看扩展名
│  ├─ 音频：.mp3 / .m4a / .wav        → 直接转写
│  └─ 视频：.mp4 / .mov               → 先提取音频，再转写
│
└─ 链接 → 先做平台白名单校验
   ├─ 非 B 站域名 → 直接拒绝，不创建任务
   │                （本版本只支持 B 站）
   └─ B 站域名（bilibili.com / b23.tv 短链）
      ├─ 短链 → 跟随跳转后**重新校验域名**，防跳转绕过
      ├─ 非 /video/BV... 或 /video/av... 形式 → 拒绝
      └─ 合法 → 解析视频信息
         ├─ 多 P / 合集 / 播放列表 → 拒绝，提示粘贴单个分 P
         ├─ 时长 > 上限（默认不限制；启用后默认 180 分钟） → 拒绝，且**不下载任何文件**
         ├─ 视频已删除 / 受限 / 需登录 → 明确报错
         └─ 可以处理 → 进入字幕检查
```

判断原则：**能在不下载的情况下拒绝，就不要下载才拒绝。** 时长和可用性都先用元信息判断。

## 4. 处理路由

```text
已通过校验
├─ 本地音频 → 语音转写
├─ 本地视频 → FFmpeg 提取 16 kHz 单声道音频 → 语音转写
└─ B 站链接 → 检查字幕
   ├─ 有可用字幕 → 提取字幕 → 标准化 → 导出   （不调用语音识别）
   └─ 无可用字幕 → 只下载音频轨 → 语音转写 → 导出
```

## 5. 字幕优先策略

**优先级：人工字幕（CC） > AI 字幕 > 语音转写。**

理由：字幕获取成本几乎为零，且是人工校对或平台生成的现成结果；只有在确实没有字幕时才付出本地转写的算力与等待时间。

判断细节（B 站特有，容易踩坑）：

1. `yt-dlp` 的 `subtitles` 里会混入 `danmaku`（弹幕 XML）。**弹幕不是字幕，必须排除**；
2. 必须显式开启字幕抓取参数，否则 `yt-dlp` 根本不会去取字幕；
3. 语言优先级：`zh-Hans` > `zh-CN` > `zh` > `zh-Hant` > `zh-TW`；
4. B 站 AI 字幕的语言代码形如 `ai-zh`，人工字幕形如 `zh-Hans`；
5. **取标题时不要设 `noplaylist`** —— 否则多 P 视频会被静默截取第一个分 P，用户拿到的是错的内容；
6. 只要字幕里存在非 `danmaku` 的条目，就不能把弹幕当字幕用。

## 6. 语音转写 Fallback

```text
音频标准化为 16 kHz 单声道 WAV
→ faster-whisper（模型/设备/精度均可配置）
→ 逐段结果 → 统一片段结构 → 导出
```

- 链接场景**只下载音频轨**（`bestaudio`），不下载视频轨；
  3 小时内容通常只有 100–250 MB，这是把"大文件"问题从源头消掉的关键；
- 下载体积超过上限立即中断并清理，不留半成品。

## 7. 失败与降级

| 情况 | 处理 | 是否算任务失败 |
| --- | --- | --- |
| 字幕存在但获取失败 | 降级为语音转写 | 否 |
| 字幕存在但解析失败 | 降级为语音转写 | 否 |
| 未配置登录凭据导致字幕不可得 | 降级为语音转写 | 否 |
| 视频时长超上限 | 拒绝，提示分段处理（默认不限制时长，此项已默认关闭） | 是 |
| **内容里没有人声（静音 / 纯音乐）** | 明确失败，提示用户确认文件；**不允许把错误文本当成功输出** | 是 |
| **文件不包含音轨** | 明确失败，提示用户确认文件 | 是 |
| 下载体积超上限 | 中断下载并清理 | 是 |
| 视频已删除 / 受限 / 需登录 | 明确报错 | 是 |
| 链接格式错误 / 非支持平台 / 多 P | 创建任务前就拒绝 | 不创建任务 |
| 转写失败 | 明确报错，提示可重试 | 是 |

底线规则：

1. **不无限重试**，网络类错误最多重试一次；
2. **不假装成功**：输出文件不完整就是失败；
3. 失败时给出**纯中文**、能告诉用户"下一步怎么办"的提示；
4. 不向用户暴露程序堆栈、原始报错或登录凭据；
5. 失败任务要清理中间文件。

## 8. 输出格式

统一输出三种产物，无论走的是字幕还是转写链路：

- `transcript.md`：带元信息头部（来源、原始地址、处理方式、生成时间）+ 带时间戳的正文；
- `transcript.txt`：只保留带时间戳的正文，便于直接复制使用；
- `result.json`：结构化结果（含分段与处理方式），供程序进一步处理。

«处理方式» 必须写真实值，不能一律写「语音转写」：

```text
语音转写                        （本地文件，或链接无字幕）
字幕提取（人工字幕）
字幕提取（AI 字幕）
```

## 9. 工具调用顺序

```text
1. 平台识别与 URL 白名单校验
2. yt-dlp 解析元信息（同时探测字幕）
3. 多 P / 时长 / 可用性校验
4. 字幕选择与标准化  ──有字幕──→ 导出
5. 只下载音频轨（无字幕时）
6. FFmpeg 统一为 16 kHz 单声道 WAV
7. faster-whisper 转写
8. 生成 Markdown / TXT / JSON
```

本地文件路径跳过第 1–5 步，从第 6 步（音频）或第 7 步（视频先提取音频）进入。

## 10. 可配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `WHISPER_MODEL` | `small` | 语音识别模型 |
| `WHISPER_DEVICE` / `WHISPER_COMPUTE_TYPE` | `cpu` / `int8` | 运行设备与精度 |
| `MAX_UPLOAD_MB` | `2048` | 本地文件上限（WAV 无压缩，故取值较大） |
| `MAX_MEDIA_MINUTES` | `0`（不限制） | 内容时长上限。实测字幕路径秒级、转写路径约 3–4 倍实时，故默认不限制；如需限制改为正整数 |
| `MAX_DOWNLOAD_MB` | `1024` | 下载体积兜底 |
| `BILIBILI_COOKIE` | 空 | 可选，但**字幕提取实际需要登录态** |

## 11. 边界与已知限制

- **画面内烧录字幕不支持**：那需要 OCR，与"字幕提取"不是同一能力；
- **多 P / 合集不支持**：一个任务只产出一份逐字稿；
- **未配置登录凭据时，B 站几乎拿不到字幕**：会静默降级为语音转写（功能正常，但更慢）；
- **长内容耗时与时长成正比**：CPU 上约为 3–4 倍实时，5 小时内容约需 75–100 分钟；默认**不限制内容时长**；
- **中文识别可能夹杂繁体字或同音错字**：属模型本身的限制，当前版本不做自动纠正；
- 只支持 B 站，抖音 / 小红书 / YouTube 尚未接入。
